**Microbench** (full table in `a_rule_vs_plan_microbench.md`):
- **Method:** CUPTI, CUDA graph, cold L2, 4 seeds × 3 interleaved rounds. All 12 Qwen3.6-35B-A3B block-FP8 linear shapes (TP1/2/4), M ∈ {1, 2, 4, 8, 16, 32, 64}.
- **The rule is never slower than CUTLASS.** Wherever it picks TRT-LLM, TRT-LLM is **1.18–1.56× faster** (min over seeds), at every M including 32 and 64.
- **The rule's threshold is conservative on SM103.** It picks CUTLASS in six cases. There:
  - (9216, 2048) M=32: TRT-LLM is 1.27× faster.
  - (4608, 2048) M=64: 1.33× faster.
  - (6144, 2048) M=64: 1.09× faster.
  - (12288, 2048) M=32: 1.03× faster.
  - (9216, 2048) M=64: 1.00×.
  - (12288, 2048) M=64: **0.86×** (slower).

  So `M·N ≤ 3·2^17` would add two clear wins and no loss on these shapes. I'm only reporting this; I have not changed the rule.
- **My old plan table vs the rule:**
  - Every TRT-LLM entry in my table is already covered by the rule.
  - The rule also covers M=32/64, which my table never planned, so it beats my table there.
  - My table beats the rule only through skinny entries, and only for the smaller shapes. For in_proj/qkv at TP1 (N = 12288 / 9216), skinny at M=1–2 is 0.90–1.11× vs TRT-LLM. That is **not** ≥ 1.10× on every seed, so those entries are dropped from (b).
